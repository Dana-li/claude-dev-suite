# 完成前验证

> **核心铁律：无新鲜验证证据，不声称完成**

---

## 铁律

> `NO COMPLETION CLAIMS WITHOUT FRESH VERIFICATION EVIDENCE`

在声称以下任何状态之前，必须先执行完整的 5 步验证流程：

- ✅ "完成了"
- ✅ "修复了"
- ✅ "通过了"
- ✅ "可以了"
- ✅ 任何表达满意或完成的话

---

## 5 步验证流程

```
                   错误
                    │
┌───────────────────▼───────────────────┐
│  你准备说"完成了" / "修好了" / "通过了"  │
└───────────────────┬───────────────────┘
                    │
                    ▼
          ┌─────────────────┐
          │ Step 1: IDENTIFY │
          │ "什么命令能证明   │
          │  这个声明?"       │
          └────────┬─────────┘
                   │
                   ▼
          ┌─────────────────┐
          │ Step 2: RUN      │
          │ 执行完整命令      │
          │ (全新运行，       │
          │  不是截取上次输出) │
          └────────┬─────────┘
                   │
                   ▼
          ┌─────────────────┐
          │ Step 3: READ     │
          │ 读取完整输出      │
          │ 检查退出码        │
          │ 统计失败数        │
          └────────┬─────────┘
                   │
                   ▼
          ┌─────────────────┐
          │ Step 4: VERIFY   │
          │ "输出确认声明?"   │
          └────────┬─────────┘
                   │
          ┌────────▼───────┐
          │ 通过?            │
          └───┬─────────┬───┘
              │ 是       │ 否
              │          │
              ▼          ▼
      ┌────────────┐ ┌──────────────┐
      │Step 5:     │ │ 不能声称完成  │
      │DECLARE     │ │ 回去继续修    │
      │"测试通过"   │ └──────────────┘
      └────────────┘
```

---

## 步骤详解

### Step 1: IDENTIFY

确定一个**能够证明你的声明的命令**。

| 你的声明 | 对应的验证命令 |
|----------|---------------|
| "这个功能完成了" | 运行该功能的所有单元测试 |
| "Bug 修复了" | 运行新增的回归测试 + 相关测试 |
| "没有引入新 Bug" | 运行完整测试套件 |
| "API 正常工作" | curl 请求 + 检查响应状态码和内容 |
| "性能没问题" | 基准测试 + 对比基线 |

### Step 2: RUN

**执行完整命令**，而不是截取之前的输出。

- ✅ `mvn test`（全新运行）
- ✅ `npm test`（全新运行）
- ✅ `curl -X GET http://localhost:8080/api/xxx`
- ❌ "上次跑了测试，通过了"（不是新鲜证据）
- ❌ "看起来应该可以"（不是证据）

### Step 3: READ

读取完整输出，特别关注：

- **退出码**：0 = 成功，非 0 = 失败
- **测试计数**：`X/Y passed` → X 和 Y 是否匹配？
- **错误信息**：是否有 ERROR、FAILURE、Exception？

### Step 4: VERIFY

**对照你的声明检查输出**：

```
声明: "测试全部通过"
输出: "34/34 passed" ✅ → 可以声明
输出: "33/34 passed" ❌ → 不能声明

声明: "API 正常工作"
输出: HTTP 200 + 正确 JSON ✅ → 可以声明
输出: HTTP 500 ❌ → 不能声明
输出: HTTP 200 + 空 body ❌ → 不能声明
```

### Step 5: DECLARE

只有在 Step 4 验证通过后，才能做出声明。

## 禁止用语

| ❌ 禁止 | ✅ 改为 |
|---------|---------|
| "现在应该可以通过了" | "运行测试后确认：34/34 通过，全部通过" |
| "看起来正确" | "curl 响应返回 HTTP 200，JSON 结构匹配规格" |
| "太棒了！完成了！"（验证前） | 先验证，再高兴 |
| "可能修好了" | "回归测试通过，新增测试通过，确认修复有效" |
| "我猜没问题" | 运行验证命令后再说 |
