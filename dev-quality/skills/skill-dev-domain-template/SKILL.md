# 领域知识注入模板

> **核心原则：插件保持通用，领域知识由用户提供**

---

## 概述

Dev Suite 是通用插件，**不包含**任何领域专业知识（SIP 协议、FFmpeg 参数、特定业务逻辑等）。

当需要领域专业知识时，通过此模板注入。

---

## 使用方式

### 方式一：在 `/dev` 流程中问答注入（推荐）

当 `skill-dev-subagent` 检测到需要领域知识时，会自动问：

```
>>> 检测到涉及 [领域名] 的任务。
>>> 请提供以下信息（或直接说"跳过"）：
>>> 1. 该领域的核心概念和规则
>>> 2. 常见注意点和坑
>>> 3. 配置规范
```

用户回答后，这些知识会被注入到子 Agent 的 prompt 中。

### 方式二：创建领域规则文件（可复用）

将领域知识保存到项目 `.claude/rules/` 下，子 Agent 会自动加载：

```
.claude/rules/
├── sip-protocol.md          ← GB28181 SIP 协议规则
├── ffmpeg-push.md           ← FFmpeg 推流参数规则  
├── database-conventions.md  ← 数据库命名规范
└── api-design.md            ← API 设计规范
```

**规则文件示例** (`.claude/rules/sip-protocol.md`)：

```markdown
# GB28181 SIP 协议开发规则

## 1. 核心字段
- SIP 服务器 ID：20 位国标编码（域编码 + 11 位序号）
- SIP 域：10 位区域编码
- 设备 ID：20 位国标编码

## 2. 端口规范
- SIP 端口范围：1024-65535
- 每个模拟器实例的 SIP 端口必须唯一
- 管理端口（Admin Port）也必须唯一

## 3. 常见陷阱
- 设备注册周期：默认 3600 秒
- 心跳间隔：60 秒
- 注册失败重试：最多 3 次
```

### 方式三：用户提供领域摘要（一次性）

对于一次性任务，直接在对话中提供：

```
在这个项目中：
- SIP 服务器 ID 格式：10位域编码 + 9位 + 1位
- 端口范围：1024-65535
- 每个实例的 SIP 端口和管理端口必须唯一，创建后不可修改
```

## 支持的领域模板

以下模板可直接要求 Dev Suite 使用：

| 领域 | 触发词 | 需要用户提供 |
|------|--------|-------------|
| **GB28181 SIP** | "SIP"、"GB28181"、"模拟器" | SIP 服务器地址、端口、域编码 |
| **FFmpeg 推流** | "FFmpeg"、"推流"、"RTSP" | FFmpeg 路径、推流参数 |
| **Spring Boot** | "Spring Boot"、"JPA" | 数据库类型、JPA 配置 |
| **Vue 重构** | "Vue"、"前端"、"Ant Design" | 组件库版本、状态管理方案 |
| **通用** | 任意 | 领域说明文本 |

## 使用示例

**用户**：帮我添加端口唯一性校验，SIP 端口和管理端口不能重复

**Dev Suite**：
```
检测到端口校验相关任务。
领域：端口管理
需确认：
1. 端口范围是多少？(默认 1024-65535)
2. 创建后是否允许修改？(默认不允许)
3. 已有实例的端口需要迁移吗？

请确认或补充。
```
