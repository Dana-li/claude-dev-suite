# 领域知识自动生成

> **核心原则：先自动探索，后用户确认，最后才问**

---

## 概述

Dev Suite 是通用插件，**不内置**任何领域专业知识。

但项目本身通常已经包含了足够的领域信息。本技能按以下优先级获取领域知识：

```
优先级 1️⃣: 项目源码 + 配置文件 + 文档 自动探索
    ↓ 成功 → 用户确认 → 生成 .claude/rules/domain-rules.md
    ↓ 失败
优先级 2️⃣: 网络搜索 + 官方文档自动抓取
    ↓ 成功 → 用户确认 → 生成 .claude/rules/domain-rules.md
    ↓ 失败或用户不认可
优先级 3️⃣: 用户问答注入 / 领域规则文件 / 一次性摘要
```

## Phase 1: 项目源码自动探索

### 扫描源

按优先级扫描以下位置：

| 优先级 | 扫描源 | 说明 |
|--------|--------|------|
| 🔴 P0 | `CLAUDE.md` | 项目主规则文件，包含架构和约束 |
| 🔴 P0 | `.claude/rules/*.md` | 已有规则文件 |
| 🟡 P1 | 配置文件 | `application.properties`, `application.yml`, `*.conf`, `*.xml` |
| 🟡 P1 | `docs/` 目录 | Wiki、手册、API 文档 |
| 🟢 P2 | Java POJO 实体 | JPA 实体字段定义、校验注解 |
| 🟢 P2 | 测试用例 | E2E 测试中的断言、Mock 数据 |
| 🔵 P3 | `package.json` | 前端依赖、脚本配置 |
| 🔵 P3 | `pom.xml` | 后端依赖、插件配置 |

### 提取内容

```markdown
### 项目配置扫描结果

#### 配置项
| 配置键 | 当前值 | 来源 |
|--------|--------|------|
| sip.server.port | 8116 | application.properties |
| device.count | 20000 | application.properties |
| media.max.streams | 10 | application.properties |

#### 实体字段约束
| 实体 | 字段 | 约束 | 来源 |
|------|------|------|------|
| GbSimulatorInstance | sipPort | @NotNull, range? | InstanceController |
| GbSimulatorInstance | channelCount | 可修改? | 前端逻辑 |

#### 项目约定
- 前端使用 Ant Design Vue 4.x
- 后端使用 Spring Boot 3.2.5 + H2
- SIP 编解码手写（禁止第三方 SIP 库）
- FFmpeg 推流（禁止 JavaCV）
```

## Phase 2: 网络搜索补充

当 Phase 1 提取的信息不足以覆盖领域知识时，自动搜索网络资料：

### 搜索策略

| 领域 | 搜索关键词 |
|------|-----------|
| **SIP/GB28181** | `GB/T 28181-2016 SIP 协议 配置规范` `SIP 服务器 国标编码 规则` |
| **FFmpeg** | `FFmpeg RTSP 推流 参数` `FFmpeg H264 编码 选项` |
| **Spring Boot** | `Spring Boot 3.2 JPA 最佳实践` `H2 数据库 生产配置` |
| **Vue/Ant Design** | `Ant Design Vue 4 表单 校验 模式` |

### 搜索结果处理

```markdown
### 网络搜索结果

#### GB28181 SIP 协议
- SIP 服务器 ID：20 位国标编码，格式：<域编码:10位> + <序号:9位> + <标识:1位>
- SIP 域：10 位行政区域编码
- 设备 ID：20 位国标编码
- 注册认证流程：401 摘要认证

#### FFmpeg 推流
- 常用参数：-re -stream_loop -1 -i [input] -c:v libx264 -f rtsp [output]
- 推流命令建议使用绝对路径
```

## Phase 3: 生成领域规则文件

将探索结果结构化输出到 `.claude/rules/domain-rules.md`：

```markdown
---
# 自动生成：项目领域规则
# 来源：项目源码探索 + 网络搜索
# 日期：YYYY-MM-DD
# 请审阅后确认或修改
---

## 1. [领域名称]
### 配置规范
...（来自 Phase 1 的配置扫描）

### 约束规则
...（来自 Phase 1 的实体和代码约束）

### 协议/技术参考
...（来自 Phase 2 的网络搜索）
```

## Phase 4: 用户确认

生成后向用户展示摘要：

```
>>> 我已自动探索本项目并提取了以下领域规则：

>>> 📄 配置项提取：12 项（sip.server.port, device.count, ...）
>>> 📄 实体约束提取：5 项（sipPort 必填, channelCount 可修改, ...）
>>> 📄 网络搜索补充：2 条（SIP 国标编码格式, FFmpeg 推流参数）
>>> 📄 已生成草稿：.claude/rules/domain-rules.md

>>> 请选择：
>>> 1. ✅ 认可，直接使用
>>> 2. ✏️ 需要修改（告诉我改哪里）
>>> 3. ❌ 不满意，我用其他方式提供
```

---

## Phase 5: 回退到三种注入方式

### 方式 A：问答注入
技能主动问用户领域知识，一次性注入到当前会话。

### 方式 B：用户创建规则文件
用户在 `.claude/rules/` 下手动创建领域规则文件。

### 方式 C：一次性摘要
用户直接告诉技能领域要点，注入到子 Agent prompt。

---

## 使用方式

| 场景 | 触发方式 |
|------|----------|
| 子 Agent 自动调用 | `skill-dev-subagent` 检测到领域任务时自动触发 |
| 手动触发 | `/skill-dev-domain` |
| 重新探索 | `/skill-dev-domain --refresh`（强制重新搜索） |
